# 项目开发规范

本文档定义了本项目的开发规范和约定，所有开发者（包括AI助手）在参与项目时都应遵循这些规范。

---

## 📁 文件组织规范

### 1. 目录结构约定

```
coding/
├── agents/              # AI Agent 模块
├── skills/              # 技能模块
├── mcp_servers/         # MCP 服务器
├── tests/               # 测试文件
├── debug/               # 调试脚本
├── config/              # 配置文件
├── generated_project/   # 生成的项目输出目录
│   ├── src/            # 生成的源代码
│   ├── tests/          # 生成的测试代码
│   └── docs/           # 生成的文档
├── docs/                # 英文技术文档
├── 文档/                # 中文文档
│   ├── 开发文档/        # 开发相关文档
│   ├── 历史文档/        # 历史版本文档
│   └── 用户文档/        # 用户使用文档
└── ...
```

### 2. 文件命名规范

#### Python代码文件
- **格式**: `snake_case.py`
- **示例**: `api_designer.py`, `code_skill.py`, `requirement_analyst.py`

#### 文档文件
- **中文文档**: 使用中文命名，描述性强
  - ✅ `项目概览.md`
  - ✅ `快速开始.md`
  - ✅ `API设计器优化文档-YAML格式降低Token消耗.md`
  - ✅ `Token优化更新总结.md`
  - ❌ `PROJECT_OVERVIEW.md` (应使用中文)
  - ❌ `API_DESIGNER_OPTIMIZATION.md` (应使用中文)

- **英文技术文档**: 仅用于纯技术规范或API文档
  - ✅ `USAGE.md` (使用指南)
  - ✅ `API.md` (API参考)
  - ✅ `ENHANCED_CODE_SKILL.md` (技术规范)

#### 配置文件
- **格式**: `lowercase_with_underscores.json` 或 `lowercase_with_underscores.yaml`
- **示例**: `agent1_config.json`, `skill_config.yaml`

#### 测试文件
- **格式**: `test_*.py`
- **示例**: `test_api_designer.py`, `test_code_skill.py`

## 📂 文件存放位置规范

### 1. 生成的文档

**规则**: 所有生成的文档必须放入对应的目录，不能放在项目根目录

| 文档类型 | 存放位置 | 示例 |
|---------|---------|------|
| 技术优化文档 | `docs/` 或 `文档/开发文档/` | `API设计器优化文档-YAML格式降低Token消耗.md` |
| 更新总结 | `docs/` 或 `文档/开发文档/` | `Token优化更新总结.md` |
| 用户指南 | `文档/用户文档/` | `UI使用指南.md` |
| 开发文档 | `文档/开发文档/` | `架构设计文档.md` |
| 历史文档 | `文档/历史文档/` | `Bug修复总结-v1.0.md` |

### 2. 生成的代码

**规则**: 所有生成的代码必须放入 `generated_project/` 目录

```
generated_project/
├── src/                 # 源代码
│   ├── main.py
│   ├── models/
│   ├── services/
│   └── utils/
├── tests/               # 测试代码
│   ├── test_main.py
│   └── ...
├── docs/                # 项目文档
│   ├── requirement.json
│   ├── architecture.json
│   ├── api_spec.json
│   └── ...
└── README.md            # 项目说明
```

### 3. 临时文件和日志

**规则**: 临时文件和日志放入专门的目录

| 文件类型 | 存放位置 |
|---------|---------|
| 调试日志 | `debug/logs/` |
| 修复日志 | `generated_project/docs/fix_log.json` |
| 临时文件 | `temp/` 或 `.temp/` |
| 缓存文件 | `.cache/` |

## 📝 代码规范

### 1. Python代码风格

- **遵循 PEP 8** 标准
- **缩进**: 4个空格
- **行长度**: 最大120字符
- **导入顺序**: 标准库 → 第三方库 → 本地模块

### 2. 文档字符串

```python
def function_name(param1: str, param2: int) -> dict:
    """
    函数简短描述

    Args:
        param1: 参数1的描述
        param2: 参数2的描述

    Returns:
        返回值的描述

    Raises:
        ExceptionType: 异常情况描述
    """
    pass
```

### 3. 类型注解

- **必须**: 所有公共函数和方法都应有类型注解
- **推荐**: 类属性也应有类型注解

```python
from typing import Dict, List, Optional

def process_data(data: List[str], config: Optional[Dict] = None) -> Dict[str, Any]:
    """处理数据"""
    pass
```

## 🎨 UI和用户体验规范

### 1. 控制台输出

- **使用 `print_safe()`**: 确保Windows兼容性
- **使用emoji替代**: 通过 `EMOJI_MAP` 映射
- **格式化输出**: 使用清晰的分隔符和缩进

```python
from utils import print_safe

print_safe("=" * 70)
print_safe("🚀 Starting workflow...")
print_safe("  [1/6] Analyzing requirements...")
print_safe("  ✅ Requirements analyzed")
```

### 2. 进度显示

- **阶段标识**: 使用 `[1/6]`, `[2/6]` 等标识进度
- **状态标识**: 使用 `✅`, `❌`, `⚠️` 等标识状态
- **详细信息**: 使用缩进显示详细信息

```python
print_safe("\n[2/6] Design Phase")
print_safe("  [2.1] Designing architecture...")
print_safe("  ✅ Architecture designed")
print_safe("  [2.2] Designing API...")
print_safe("  ✅ API designed (YAML format)")
print_safe("     Tokens: 1234 input + 567 output = 1801 total")
```

### 3. Token使用显示

**必须显示的信息**:
- Input tokens
- Output tokens
- Total tokens
- 格式类型 (YAML/JSON)
- 预估成本（如适用）

```python
if "token_usage" in result:
    tokens = result["token_usage"]
    print_safe(f"  ✅ API designed ({result.get('format', 'unknown').upper()} format)")
    print_safe(f"     Tokens: {tokens['input_tokens']} input + {tokens['output_tokens']} output = {tokens['total_tokens']} total")
```

## 📊 数据和结果规范

### 1. 返回值格式

所有Agent和Skill的返回值应遵循统一格式:

```python
# 成功返回
{
    "success": True,
    "data": {...},
    "token_usage": {
        "input_tokens": 1234,
        "output_tokens": 567,
        "total_tokens": 1801
    },
    "format": "yaml",  # 或 "json"
    "timestamp": "2026-01-29T10:30:00"
}

# 失败返回
{
    "success": False,
    "error": "错误描述",
    "details": {...},
    "stage": "api_design",
    "timestamp": "2026-01-29T10:30:00"
}
```

### 2. Token使用追踪

**所有调用Claude API的地方都必须追踪token使用**:

```python
response = self.client.messages.create(...)

# 提取token使用信息
token_usage = {
    "input_tokens": response.usage.input_tokens,
    "output_tokens": response.usage.output_tokens,
    "total_tokens": response.usage.input_tokens + response.usage.output_tokens
}

return {
    "success": True,
    "data": result,
    "token_usage": token_usage
}
```

### 3. 报告格式

生成的报告应包含:
- 阶段信息
- 时间戳
- Token使用统计
- 详细结果
- 摘要信息

```python
report = {
    "stage": "design",
    "status": "completed",
    "timestamp": datetime.now().isoformat(),
    "token_usage": token_usage,
    "api_format": "yaml",
    "data": {...},
    "summary": {...}
}
```

## 🚀 性能和优化规范

### 1. Token优化

- **优先使用YAML**: 比JSON节省40%的token
- **简洁的提示词**: 避免冗余描述
- **合理的max_tokens**: 根据实际需要设置
- **确定性输出**: 使用temperature=0.0

### 2. 成本控制

- **追踪token使用**: 所有API调用都应记录
- **显示成本估算**: 在UI中显示预估费用
- **优化重试策略**: 避免不必要的重试

### 3. 性能监控

```python
# 记录执行时间
start_time = time.time()
result = execute_task()
duration = time.time() - start_time

print_safe(f"  ⏱️  Execution time: {duration:.2f}s")
```

## 🔄 版本控制规范

### 1. Git提交信息

格式: `<type>(<scope>): <subject>`

类型:
- `feat`: 新功能
- `fix`: 修复bug
- `docs`: 文档更新
- `style`: 代码格式调整
- `refactor`: 重构
- `test`: 测试相关
- `chore`: 构建/工具相关

示例:
```
feat(api-designer): 使用YAML格式降低token消耗
fix(ui): 修复token使用显示问题
docs: 添加项目开发规范文档
```

### 2. 分支管理

- `main`: 主分支，稳定版本
- `develop`: 开发分支
- `feature/*`: 功能分支
- `fix/*`: 修复分支
